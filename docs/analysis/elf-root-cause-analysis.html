已确认: ELF 编码器原始输出即与 BGE 文档向量正交(余弦 -0.028), 根因是向量空间错位, 与扩散参数无关

关键观察: 12 组不同扩散参数的 ELF 指标几乎完全相同 → 扩散增强(加噪/去噪/CFG) 不是决定指标的因素; 决定因素在 ELF 链路的上游——查询向量本身。

3. 根因分析(三层)

3.1 直接原因: 查询向量与文档向量不在同一向量空间

评测的双链路设计(计划 §2.2/§2.3, docs/diffusion-rag-plan.md)是 "同一向量库, 仅替换查询编码":

  • 文档侧(两条链路共享): BGE 编码器 BAAI/bge-base-en-v1.5 → 768-dim;
  • baseline 查询侧: 同一个 BGE 编码器 → 768-dim, 与文档同空间, 内积正常(0.466);
  • ELF 查询侧: ELFNativeEncoder(T5-small + 投影层) → 768-dim, 但这是 另一个独立训练的向量空间。

两个空间虽然维度相同(768), 但 BGE 与 T5 投影是各自独立训练的, 没有对齐约束。 单位向量在不同空间中点积期望接近 0——这正是 0.007 的来源。计划文档中 "向量维度: 768(与 ELF 输出对齐)"(plan §2.2)隐含了"同维即对齐"的假设, 该假设被数据否定。

3.2 深层原因一: 扩散增强使用"占位速度场", 无真实 denoiser

即使空间错位的问题不存在, 当前增强链路也没有接入真实训练过的去噪模型。 ELFPipeline 的默认速度场是 _default_model_fn(向原点收缩的简易近似, 代码注释明确写着"当真实扩散模型不可用时回退使用"), 且噪声调度 σ(t)=t 在 noise_t=0.3~0.6 下会注入相当强度的噪声。去噪输出与原始向量相关性极低 (shift_cos=0.026), 增强并未产生"语义增强", 而是把向量推离了原始方向。

3.3 深层原因二: 扩散噪声尺度与向量分布不匹配

即使速度场正确, add_noise 用 z_t = z_0 + σ(t)·ε 加噪, 其中 σ(t)=t。对单位向量, noise_t=0.5 意味着噪声能量为信号能量的 50%, 向量已严重污染; 若去噪不精确(见 3.2), 输出将远离 z_0。这也是 shift_l2≈1.40(接近两个随机单位向量的期望距离)的原因。

4. 相关代码

4.1 查询侧: ELF 增强链路(编码 → 加噪 → 去噪 → 归一化)

src/elf/pipeline.py · ELFPipeline.enhance() L125-176

def enhance(self, text, steps=2, noise_t=DEFAULT_NOISE_T, cfg_scale=2.0, rng=None):
    # Step 1: 编码 —— ELFNativeEncoder(T5-small → 投影 768-dim)
    z_0 = self.encoder.encode(text)
    # Step 2: 加噪 —— z_t = z_0 + σ(t)·ε
    z_t = add_noise(z_0, t=noise_t, rng=rng)
    # Step 3: Velocity 级 CFG 去噪(默认速度场 = 向原点收缩的占位实现)
    cond_fn = self._model_fn_cond or _default_model_fn        # ← L152
    uncond_fn = self._model_fn_uncond or _default_model_fn    # ← L153
    z_out = denoise_with_cfg(z_t, cond_fn, uncond_fn, steps=steps,
                             cfg_scale=cfg_scale, t_start=noise_t)
    # Step 4: L2 归一化
    z_out = z_out / np.linalg.norm(z_out)

src/elf/pipeline.py · _default_model_fn L35-51 — 占位速度场, 未接真实 denoiser

def _default_model_fn(z, t):
    """简易去噪速度场: 朝原点收缩。当真实扩散模型不可用时回退使用。"""
    noise_scale = sigma(t)
    if noise_scale > 1e-8:
        return -z / noise_scale          # 朝原点收缩, 与查询内容无关
    return np.zeros_like(z)

4.2 噪声调度与去噪推进

src/elf/diffusion.py · sigma L31-40 / add_noise L48-87 / denoise_with_cfg L157-233

def sigma(t):           # L31  线性噪声调度
    return t

def add_noise(z_0, t, rng):            # L48
    eps = rng.standard_normal(size=z_0.shape, dtype=np.float32)
    z_t = z_0 + sigma(t) * eps         # 对单位向量, t=0.5 即 50% 噪声能量
    return z_t

6. 可能的解决办法(按成本从低到高)

方案 A: 先验证, 再对症下药(必做, 零成本)

执行第 5 节实验, 确认错位层。后续方案按实验结果选择。

方案 B: 文档侧也使用 ELF 编码器(若错位在编码层, 首选)

把文档向量库也换成 ELFNativeEncoder 编码, 使查询与文档落在同一 (ELF) 空间, 双链路各自"自洽":

  • 改动点: run_benchmark 文档准备阶段按 method 切换编码器(当前恒用 BGE); 或为 ELF 链路单独建索引(放弃"双链路共享索引"计划假设);
  • 代价: 全库文档重新编码(CPU 上 nfcorpus 542 篇约 8 分钟, 有缓存机制可复用); 文档量大的数据集耗时显著, 可配合批量编码 encode_batch;
  • 效果: 保证 ELF 链路检索有效(相似度从 0.007 回到正常水平), 指标才能反映 "增强"的真实效果。

方案 C: 接入真实扩散 denoiser, 校准噪声调度(若错位在扩散层)

  • 用训练过的 velocity/score 模型替换 _default_model_fn 占位实现 (ELFPipeline(model_fn_cond=..., model_fn_uncond=...) 已预留注入接口);
  • 校准 sigma(t) 与 ELF 训练时一致, 或降低 noise_t(如 0.1~0.2) 使去噪更易收敛; 增加 steps 验证 ODE 收敛性;
  • 检查 denoise_with_cfg 数值稳定性(dt 符号、t_start 推断)。

方案 D: 使 ELF 输出空间与 BGE 对齐(若必须保持共享索引)

  • 用 BGE 文档/查询向量作为监督目标, 微调 _projection(或加一层可学习对齐变换); ELF 增强在"已对齐"的 BGE 空间内进行;
  • 代价最高(需要训练数据/目标函数), 仅在双链路必须共享同一向量库且不能换文档编码时考虑。

方案 E: 短期降噪实验(快速试错)

若想快速确认扩散链路影响, 可临时把 noise_t 降到 0(等于不做扩散, 只走 ELF 编码), 对比指标: query_doc_sim 若仍 ≈ 0.007 → 编码错位坐实, 直接转方案 B。
