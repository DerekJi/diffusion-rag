## 问题列表

### [高] 死参数 / `_load_elf_checkpoint` 的 `t5_model` 从未使用
**文件**: `src/elf/native_encoder.py:203`
**问题**: `_load_elf_checkpoint(t5_model, projection, checkpoint_path, device)` 接受 `t5_model` 参数并在 docstring 中描述为 "T5 编码器模型"，但函数体从未使用它——仅加载了投影层权重。这导致 ELF checkpoint 中可能存在的 T5 编码器微调权重被丢弃，模型实际上只是标准 `t5-small` + 随机初始化（或 checkpoint 中加载的）投影层。
**建议**: 两个方向：(a) 如果 checkpoint 确实不含 T5 权重，删除 `t5_model` 参数并更新 docstring；(b) 如果 checkpoint 含 T5 权重，补充 `t5_model.load_state_dict()` 逻辑。目前是误导性接口。

### [高] 类 docstring 声称有 `encoder` 属性但实际不存在
**文件**: `src/elf/model_wrapper.py:35`
**问题**: `ELFModelWrapper` 的 class docstring 的 Attributes 中列出 `encoder: 底层 ELFNativeEncoder 实例（提供条件编码）。`，但 `__init__` 只接受 `cond_vec` 和 `use_conditioning`，类根本没有 `encoder` 属性。这是从早期设计残留的文档错误，会误导调用者。
**建议**: 删除 docstring 中的 `encoder` 行，或补充真实的 `encoder` 引用。

### [中] `_velocity_with_condition` / `_velocity_unconditioned` 是纯数学模拟而非真实模型推理
**文件**: `src/elf/model_wrapper.py:82-131`
**问题**: 两个内部速度场方法（`cond - z / t` 和 `-z / t`）是完全手写的数学近似，并未调用任何 ELF 模型或神经网络。这与 task 描述中的 "包装 ELF 模型的 forward() 为速度场函数" 不一致，也与 class docstring 的 "将 ELF 原生模型的 forward() 包装为" 矛盾。当前实现只是 shape/dtype 兼容的占位。
**建议**: (a) 如果这是有意暂缓（Phase 2.3 分阶段交付），在 class/module docstring 中明确标注为 `TODO` 或 `FIXME`；(b) 补充实际的 ELF 模型前向调用。

### [中] `transformers` 导入缺少 try/except 守卫——与 `elf/encoder.py` 风格不一致
**文件**: `src/elf/native_encoder.py:13`
**问题**: `elf/encoder.py` 对 `sentence_transformers` 做了 `try/except ImportError` 守卫并设置 `_HAS_SENTENCE_TRANSFORMERS` 标志，在 `__init__` 中给出友好的 `RuntimeError` 提示。`native_encoder.py` 直接 `import torch` 和 `from transformers import ...`，无守卫。若 `transformers` 未安装，导入模块即崩溃，用户体验差。
**建议**: 与 `elf/encoder.py` 保持一致——添加 `try/except ImportError` 守卫，在实例化时抛出清晰的 `RuntimeError("请安装: pip install transformers")`。

### [中] `_load_elf_checkpoint` 的 `checkpoint_path` 分支逻辑有歧义
**文件**: `src/elf/native_encoder.py:215-216`
**问题**: 
```python

```

**建议**: 显式区分逻辑——例如用 `os.path.isdir(checkpoint_path)` 判断是否为本地路径，或增加 `local_path: bool = False` 参数。

### [低] `native_encoder.py` 中 `import numpy as np` 与 `from __future__ import annotations` 并存但 `encoder.py` 无 `__future__` 导入

+
+将 ELF 原生模型的  包装为与 denoise() 兼容的速度场函数，
+支持条件/无条件两种模式（用于 CFG 引导）。

+

+from numpy.typing import NDArray

+class ELFModelWrapper:
+    """ELF 模型速度场包装器。
+
+    将 ELF 原生模型的 forward() 包装为与 denoise() 兼容的速度场函数，
+    支持条件/无条件两种模式（用于 CFG 引导）。
+
+    签名兼容::
+
+        model_fn(z: NDArray[np.float32], t: float) -> NDArray[np.float32]
+
+    Attributes:
+        encoder: 底层 ELFNativeEncoder 实例（提供条件编码）。
+        cond_vec: 条件文本的编码向量（条件模式使用）。
+        use_conditioning: 是否使用条件编码。
+    """
+
+    def __init__(
+        self,
+        cond_vec: NDArray[np.float32] | None = None,
+        use_conditioning: bool = True,
+    ) -> None:
+        """初始化速度场包装器。
+
+        Args:
+            cond_vec: 条件文本的编码向量，shape (768,)。
+                      若为 None 且 use_conditioning=True，则回退到无条件速度场。
+            use_conditioning: 是否使用条件编码。False 时为无条件模式。
+        """
+        self.cond_vec = cond_vec
+        self.use_conditioning = use_conditioning
+
+        logger.debug(
+            "ELFModelWrapper 已初始化 (use_conditioning=%s, cond_vec=%s)",
+            use_conditioning,
+            "provided" if cond_vec is not None else "None",
+        )
+
+    def __call__(self, z: NDArray[np.float32], t: float) -> NDArray[np.float32]:
+        """预测速度场。
+
+        根据当前状态 z 和时间 t，结合条件向量（若有）预测速度。
+
+        Args:
+            z: 当前（加噪）向量。shape (d,) 或 (n, d)。
+            t: 当前时间步 ∈ [0, 1]。
+
+        Returns:
+            速度向量 v，shape 与 z 相同。
+        """
+        if z.dtype != np.float32:
+            raise ValueError(f"z 必须是 float32，got {z.dtype}")
+
+        is_1d = z.ndim == 1
+        z_2d = np.atleast_2d(z)
+
+        # 计算速度场
+        if self.use_conditioning and self.cond_vec is not None:
+            v = self._velocity_with_condition(z_2d, t)
+        else:
+            v = self._velocity_unconditioned(z_2d, t)
+
+        return v.reshape(-1) if is_1d else v
+
+    # ── 内部速度场计算 ────────────────────────
+
+    def _velocity_with_condition(
+        self,
+        z: NDArray[np.float32],
+        t: float,
+    ) -> NDArray[np.float32]:
+        """带条件的速度场预测。
+
+        模拟 ELF 模型的条件速度场：将当前状态推向条件向量方向。
+
+        Args:
+            z: 当前向量，shape (n, d)。
+            t: 当前时间步。
+
+        Returns:
+            速度向量，shape (n, d)。
+        """

+        # 速度方向: 朝向条件向量，幅度与噪声水平成反比
+        direction = cond - z  # (n, d)
+        noise_scale = max(t, 1e-8)
+        v = direction / noise_scale
+        return v
+
+    def _velocity_unconditioned(
+        self,
+        z: NDArray[np.float32],
+        t: float,
+    ) -> NDArray[np.float32]:
+        """无条件速度场预测。
+
+        模拟 ELF 模型的无条件速度场：向原点收缩。
+
+        Args:
+            z: 当前向量，shape (n, d)。
+            t: 当前时间步。
+
+        Returns:
+            速度向量，shape (n, d)。
+        """
+        noise_scale = max(t, 1e-8)
+        v = -z / noise_scale
+        return v
+

+            texts: 文本列表。

+            normalized = torch.nn.functional.normalize(projected, p=2, dim=1)

+
