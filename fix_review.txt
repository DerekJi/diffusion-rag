## 问题列表

### [中] 公共 API 设计 / `batch_size` 参数未透传
**文件**: `src/elf/pipeline.py:211`
**问题**: `enhance_batch` 调用 `self.encoder.encode_batch(texts)` 时未传递 `batch_size` 参数，完全依赖编码器的默认值 (32)。对于大批量文本（如评测中数千条），用户无法通过 `enhance_batch` 控制编码器的内部批次大小，需直接操作 `encoder` 对象。
**建议**: 为 `enhance_batch` 增加可选参数 `encode_batch_size: int = 32`，并透传给 `self.encoder.encode_batch(texts, batch_size=encode_batch_size)`。这是低风险的小改动，能提升 API 的灵活性。

### [中] 测试覆盖 / 缺少 `enhance_batch` 输出的 L2 归一化显式断言
**文件**: `tests/test_elf_pipeline.py:329-397`
**问题**: 新增的 4 个 `enhance_batch` 测试中，没有一个直接断言批量输出的每行 L2 范数 ≈ 1.0。虽然 `test_enhance_batch_matches_individual` 通过与 `enhance`（已有归一化测试）对比间接覆盖，但若未来 `enhance` 的归一化逻辑被意外移除，两个方法会同时失效而不被发现。
**建议**: 在 `test_enhance_batch_larger_batch` 或单独新增一个测试中，加入显式的 L2 归一化检查：
```python
norms = np.linalg.norm(vecs, axis=1)
assert np.allclose(norms, 1.0, atol=1e-5)
```

### [低] 测试辅助类 / `_FakeEncoder` 返回类型注解不精确
**文件**: `tests/test_elf_pipeline.py:38-43`
**问题**: `_FakeEncoder.encode` 和 `encode_batch` 返回类型标注为 `np.ndarray`，而真实编码器接口返回 `NDArray[np.float32]`。虽然不影响运行，但在 IDE 类型检查中会导致不一致。
**建议**: 将返回类型统一改为 `NDArray[np.float32]`：
```python
def encode(self, text: str) -> NDArray[np.float32]:
    ...
def encode_batch(self, texts: list[str], batch_size: int = 32) -> NDArray[np.float32]:
    ...
```

### [低] 测试辅助类 / 遗留随机 API
**文件**: `tests/test_elf_pipeline.py:26`
**问题**: `_FakeEncoder.__init__` 使用 `np.random.RandomState(42)`（NumPy 遗留 API），而项目其余代码已统一使用 `np.random.default_rng()`（新 API）。不影响行为，但风格不一致。
**建议**: 改为 `np.random.default_rng(42)` 并调整后续调用（`rng.standard_normal` 等）。

### [低] 批量归一化 / 冗余 `np.asarray` 包装
**文件**: `src/elf/pipeline.py:229`
**问题**: `np.linalg.norm(z_out, axis=1, keepdims=True)` 已返回 `ndarray`，外层 `np.asarray(...)` 是空操作，增加阅读成本。
**建议**: 简化为：
```python
norms = np.linalg.norm(z_out, axis=1, keepdims=True)
```
